IFDD — Integration of Federated Data Domains

The data stays where it is produced. Integration happens through shared meaning instead of shared storage.

The idea

  • Domains keep their data. Every domain — a team, a system, a person — publishes its own records from its own endpoint and stays responsible for them.
  • A shared schema replaces a shared system. Records are checked against published JSON-LD contexts and vocabularies and served as JSON-LD. A model template that generates these descriptions from LinkML exists as a prototype (model).
  • Identity is separate from location. Identifiers are permanent; hosts are operational and may change.

What runs under ifdd.de

Only this website. Addresses such as id.ifdd.de or schema.<domain>.ifdd.de in the concept documents describe the naming model; they are not operated as public services. The software runs wherever someone deploys it.

Met a name like breaker.grid.example.ifdd.de? That is an example name — see the example namespace.

Status

Early and open. The concepts are written down, and the first services exist as cookiecutter templates and Python packages, together with a tool that builds a complete installation from them. Expect the naming rules to stay stable and everything else to move.

Who is behind it

ifdd.de contributors — an open-source working group around the GitHub organisation ifdd-de. All repositories are public and licensed under BSD-3-Clause. Issues and pull requests are welcome in the repository they concern; for anything else write to maintainers@ifdd.de.
