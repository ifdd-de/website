The example namespace

You probably met a name like breaker.grid.example.ifdd.de in documentation, test data or a schema and wondered what is behind it. Nothing real — on purpose.

A fictional organisation

example is a fictional organisation. IFDD documentation, templates and test data use it so that no real organisation, system or host name appears in them. It runs an electricity grid and has two domains:

  • grid keeps the asset register, for example circuit breakers;
  • ops keeps the maintenance plan.

All data of the example is generated. It describes no real equipment.

Two kinds of names

Context names

breaker.grid.example.ifdd.de, maintenance.ops.example.ifdd.de

A context name names a JSON-LD context. It is written like a DNS name and read from the right: breaker belongs to grid, which belongs to example. Such a name does not resolve and does not need to. Access rights follow it: a client with a read role and the pattern grid.example.ifdd.de may read every context below it.

Host names of demo nodes

<node>.grid.example.ifdd.de

Reserved for demo nodes. None exists today.

A name under example.ifdd.de is therefore not necessarily a host. If it does not resolve, nothing is broken. example.ifdd.de itself only leads to this page.

Why a namespace of its own

Examples need names that look like the real thing but can never collide with a real domain. The idea is the same as with example.org; example.ifdd.de, however, is reserved only by a decision of this project, not by a standard.
